# Stakeholder Requirements

## Persona 1: Operational manager

**Need:** Understand whether demand and waiting performance are changing and
where investigation is required.

**User story:** As an operational manager, I want a concise view of demand,
admissions and long waits so that I can prioritise service-review discussions.

## Persona 2: Performance analyst

**Need:** Reconcile figures, compare periods and investigate provider variation.

**User story:** As a performance analyst, I want transparent KPI definitions,
filters and exportable data so that I can validate and explain reported results.

## Persona 3: Executive user

**Need:** Understand the current position, direction of travel and material
exceptions without technical detail.

**User story:** As an executive user, I want a small number of clearly explained
indicators so that I can ask focused questions and monitor improvement.

## Persona 4: Data quality lead

**Need:** Know whether reported figures are complete, valid and traceable.

**User story:** As a data quality lead, I want failures and source lineage shown
clearly so that unreliable outputs are not released.

## Information requirements

- Current and historical demand
- Emergency admission volume and rate
- Four-hour performance where supported
- Long waits after decision to admit
- Provider and system variation
- Month-on-month and year-on-year change
- Data completeness and validation status
- Metric definitions and analytical caveats

## Stakeholder engagement plan for portfolio simulation

Because this is an independent portfolio project, stakeholder requirements are
explicit analytical assumptions. They will be tested through:

1. Review against current NHS analyst role responsibilities.
2. Usability review by a non-technical reader.
3. Reconciliation review of every dashboard KPI.
4. Documented change requests in the project decision log.
